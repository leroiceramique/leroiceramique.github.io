ما هذه الحزمة؟
  أول مرحلة من نظام نقل التحديث من التجريبية إلى الإنتاج من داخل اللوحة.
  هذه المرحلة عرض وفحص فقط — لا يوجد فيها أي مسار يكتب على GitHub إطلاقاً،
  ولا أي دمج تلقائي، ولا أي تغيير في الإنتاج أو قواعد البيانات (إضافة جدول
  سجل جديد فقط بصيغة IF NOT EXISTS التراكمية المعتادة).

الملفات الثلاثة للرفع على فرع Staging فقط (كالعادة، من GitHub ويب):
  1) bot.py        → استبدال الموجود
  2) pwa.html      → استبدال الموجود
  3) CHANGELOG.md  → استبدال الموجود
  ⚠️ لا ترفع شيئاً إلى main. لا ملفات Pages في هذه الحزمة (sw.js كما هو).

خطوات الرفع (نفس روتينك المعتاد):
  GitHub ← المستودع ← بدّل إلى فرع Staging ← Add file / Upload files
  ← ارفع الملفات الثلاثة ← Commit مباشرة إلى Staging.
  Render سيعيد نشر خدمة التجريبية تلقائياً (دقيقة-دقيقتين).

ماذا تختبر بعد ظهور «الإصدار 63» في شاشة البداية؟
  1) افتح التطبيق على التجريبية ← الإعدادات ← ستجد بطاقة جديدة
     «🚢 إدارة إصدارات التطبيق» (تظهر لحسابك أنت فقط — المالك).
  2) «🧭 فتح لوحة الإصدارات» ← الشاشة تعرض:
     - بطاقتا 🏭 الإنتاج و🧪 التجريبية: إصدار كل خدمة من الاستطلاع الحي
       + حالة الوصول + آخر نشر (تاريخ آخر كوميت لكل فرع).
       المتوقع الآن: الإنتاج 61 · التجريبية 63 بعد النشر.
  3) «🔄 فحص التحديثات» ← يجلب المقارنة الرسمية من GitHub:
     المتوقع: التجريبية متقدمة بـ كوميت v187 · ملفات متغيرة:
     bot.py وpwa.html وCHANGELOG.md (+ أسماء الكوميتات المعلّقة).
     ملاحظة: بدون توكن حد GitHub المجهول 60 فحصاً/ساعة لكل IP —
     إن ظهرت رسالة الاستنفاد أعد الفحص بعد قليل أو ركّب التوكن (أدناه).
  4) «سجل عمليات النقل» ← سيظهر «لا عمليات نقل بعد» — طبيعي:
     يبدأ التسجيل مع حزمة الدمج القادمة.
  5) تحقق أن كل الميزات السابقة تعمل كالمعتاد (المخزون، الحركة،
     المستخدمون، الثيم الشخصي) — هذه الحزمة لا تلمس أي شيء منها.

التوكن (اختياري الآن، ضروري قبل مرحلة الدمج):
  GitHub ← Settings ← Developer settings ← Personal access tokens
  ← Fine-grained tokens ← Generate:
    - Repository access: Only select repositories ← هذا المستودع فقط
    - Permissions: Contents = Read and write · Pull requests = Read and write
    - Expiration: 90 يوماً (أقل مدة متاحة)
  ثم في Render: خدمة الإنتاج (produit) ← Environment ← أضف:
    GH_RELEASE_TOKEN = <التوكن>
  يُضاف لاحقاً أيضاً: STAGING_PUBLIC_URL (افتراضيه مضبوط في الكود أصلاً).
  التوكن لا يُكتب في أي ملف ولا يُرسل للواجهة ولا يظهر في السجلات.

ماذا لن تفعل هذه الحزمة (مضمون شرطك):
  - لا تعمل على الإنتاج إطلاقاً (الرفع على Staging فقط).
  - لا دمج ولا كتابة على GitHub — الأزرار القادمة في حزمة v188 بعد موافقتك.
  - لا نقل بيانات بين قاعدتي التجريبية والإنتاج.
  - لا تغيير في أي صلاحية أو سر أو إعداد قاعدة بيانات قائم.

المتغيرات الجديدة (كلها اختيارية ولها افتراضيات مضبوطة):
  GH_RELEASE_TOKEN · GH_RELEASE_REPO · GH_BASE_BRANCH (main)
  · GH_SOURCE_BRANCH (Staging) · PROD_PUBLIC_URL · STAGING_PUBLIC_URL
