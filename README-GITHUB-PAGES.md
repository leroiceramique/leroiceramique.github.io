هذه الحزمة تجعل مشروع التطبيق يُفتح من رابط إنترنت ثابت على أي حاسوب:
**https://leroiceramique.github.io**

## 📦 محتويات الحزمة
| الملف | وظيفته |
|---|---|
| `index.html` | صفحة المشروع (واجهة + زر فتح التطبيق + دليل + أسئلة) — **هذا هو الملف الوحيد المطلوب للنشر** |
| `preview_orgtheme.png` / `preview_orgtheme_dark.png` / `theme_app_dark.png` | لقطات واجهة التطبيق تظهر داخل الصفحة |

## ✅ خطوات النشر (مرة واحدة — 5 دقائق)

1. **حساب GitHub**: ادخل github.com بحساب اسمه `leroiceramique`
   (إن كان اسم حسابك مختلفاً، الرابط سيصبح `https://اسم-حسابك.github.io` — والصفحة تعمل بنفس الطريقة).
2. **إنشاء المستودع**: اضغط **New repository** وسمّه **بالضبط**: `leroiceramique.github.io`
   - اختر **Public** ← **Create repository**.
3. **رفع الملفات**: في صفحة المستودع اضغط **uploading an existing file** (أو Add file ← Upload files)
   - اسحب: `index.html` + صور اللقطات الثلاث
   - اضغط **Commit changes**.
4. **تفعيل Pages**: من المستودع ← **Settings** ← **Pages** (من القائمة الجانبية)
   - Source: **Deploy from a branch**
   - Branch: **main** و Folder: **/(root)** ← **Save**.
5. **الرابط يعمل**: انتظر 1–2 دقيقة ثم افتح:
   **https://leroiceramique.github.io**
   - إن لم يفتح فوراً حدّث الصفحة بعد قليل (أول بناء يأخذ وقتاً أحياناً).

## 🔗 ربط التطبيق الحي (البيانات الحقيقية)

صفحة GitHub تعرض واجهة المشروع وتشرحه، وزر **«🚀 فتح التطبيق»** يفتح التطبيق الحي من سيرفر البوت:

- **جربها الآن على شبكتك**: أدخل عنوان السيرفر مثل `http://192.168.1.10:8080`
  (IP جهاز البوت + المنفذ) أو `http://127.0.0.1:8080` من نفس الجهاز.
- **من أي مكان في العالم**: عند نشر البوت على استضافة سحابية (Render مثلاً) ستحصل على
  رابط عام مثل `https://your-bot.onrender.com` — أدخله في خانة السيرفر واحفظ،
  فيفتح التطبيق بضغطة من أي حاسوب أو هاتف.

العنوان يُحفظ في متصفحك فقط (localStorage) ولا يُرسل لأي جهة.

## ⚖️ ما الذي يعمل وما الذي لا يعمل على github.io؟

| يعمل ✅ | لا يعمل ❌ |
|---|---|
| فتح صفحة المشروع من أي حاسوب/هاتف | تشغيل بايثون/البوت داخل GitHub (استضافتهم ثابتة فقط) |
| زر فتح التطبيق الحي من رابط السيرفر | قاعدة البيانات والجلسات داخل GitHub نفسها |
| لقطات الواجهة + الدليل + الأسئلة | استقبال طلبات `/api/*` على github.io |

> هذا طبيعي وليس قصوراً: GitHub Pages خادم ملفات ثابتة. عقل النظام (البوت + PostgreSQL)
> يعيش على سيرفرك أو استضافتك السحابية — والصفحة بوابة أنيقة إليه.

## 🔄 تحديث الصفحة لاحقاً

- عدّل `index.html` ثم ارفعه من جديد بنفس الاسم (Add file ← Upload files ← يستبدل)
- سيظهر التحديث على الرابط خلال دقيقة.
- ملاحظة: تعديل هذه الصفحة **لا يمس البوت ولا قاعدة البيانات ولا جلسات المستخدمين** إطلاقاً.

## 💡 لماذا لم نضع نسخة التطبيق الكاملة نفسها على GitHub؟

ملف `pwa.html` الكامل يحتاج خادم `/api/*` خلفه (دخول، مخزون، رسائل…) — لو رُفع وحده
ستظهر شاشة الدخول لكن لا أحد يستطيع الدخول. البوابة الحالية أصدق وأ أوضح للزوار،
والتطبيق الحي يبقى من رابط السيرفر بجلساته المحمية.
